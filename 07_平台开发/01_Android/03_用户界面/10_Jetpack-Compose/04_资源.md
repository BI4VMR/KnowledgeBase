# 主题
## MaterialTheme
### 基本应用
MaterialTheme 是 Material 3 库提供的主题组件，内置配色方案、文本样式、控件形状等公共属性，且这些属性是响应式的，当我们将控件放置在 MaterialTheme 块内部时，控件的外观将自动跟随当前主题配置进行切换。

🔴 示例一：Material 3 主题的基本用法。

在本示例中，我们以颜色属性为例，制作深色与浅色两种主题。

第一步，创建配色方案。

`Theme.kt` :

```kotlin
// 配色方案：浅色模式
private val LightColorScheme = lightColorScheme(
    primary = Color.Black
)

// 配色方案：深色模式
private val DarkColorScheme = darkColorScheme(
    // 主要颜色：文本框、按钮等元素的主色调
    primary = Color.White
)
```

`lightColorScheme()` 和 `darkColorScheme()` 是 Material 3 库内置的两套配色方案，分别对应浅色与深色模式，我们以它们为基础创建两个自定义配色方案，修改 `primary` 颜色属性，其他属性则使用默认值。

第二步，创建主题组件。

`Theme.kt` :

```kotlin
@Composable
fun MyTheme(
    // 是否启用深色模式
    darkMode: Boolean,
    content: @Composable () -> Unit
) {
    // 根据深色模式是否启用选择配色方案
    val colorScheme = if (darkMode) DarkColorScheme else LightColorScheme

    MaterialTheme(
        colorScheme = colorScheme,
        content = content
    )
}
```

MyTheme 组件用于封装 MaterialTheme，根据外部传入的 `darkMode` 参数选择前一步中创建的配色方案。

第三步，应用主题组件。

我们首先定义枚举类表示主题模式配置。

`TestUITheme.kt` :

```kotlin
enum class DarkMode {
    // 跟随系统设置
    AUTO,
    // 浅色
    LIGHT,
    // 深色
    DARK;
}
```

然后在示例 Activity 中引用 MyTheme，并根据用户选择的主题模式，设置 `darkMode` 参数。

`TestUITheme.kt` :

```kotlin
setContent {
    // 深色模式配置项
    var darkModeConfig: DarkMode by remember { mutableStateOf(DarkMode.AUTO) }
    // 是否启用深色模式
    val darkModeState = when (darkModeConfig) {
        DarkMode.AUTO -> isSystemInDarkTheme()
        DarkMode.LIGHT -> false
        DarkMode.DARK -> true
    }

    MyTheme(darkModeState) {
        Surface {
            // 顶层容器
            Column {
                /* 深色模式设置 */
                Text(text = "深色模式设置：")
                Row {
                    RadioButton(
                        selected = (darkModeConfig == DarkMode.AUTO),
                        onClick = { darkModeConfig = DarkMode.AUTO },
                    )
                    Text(text = "跟随系统")
                }
                Row {
                    RadioButton(
                        selected = (darkModeConfig == DarkMode.LIGHT),
                        onClick = { darkModeConfig = DarkMode.LIGHT },
                    )
                    Text(text = "浅色")
                }
                Row {
                    RadioButton(
                        selected = (darkModeConfig == DarkMode.DARK),
                        onClick = { darkModeConfig = DarkMode.DARK },
                    )
                    Text(text = "深色")
                }


                /* 引用主题属性 */
                Icon(
                    painter = painterResource(id = android.R.drawable.ic_dialog_alert),
                    contentDescription = null,
                    tint = MaterialTheme.colorScheme.primary
                )
            }
        }
    }
}
```

MaterialTheme 通常与 Surface 或 Scaffold 等 Material 3 容器组合使用，Column 和 Row 等基础组件并不依赖 Material 3 库，默认配置下背景为透明，如果我们既不使用 Surface 或 Scaffold；又没有明确为顶层 Column 或 Row 配置背景，就会看到 Activity 所在的 Window 背景。

用户选中某个 RadioButton 时，`darkModeConfig` 变更，关联属性 `darkModeState` 也会变更并触发 MyTheme 重组，新的配色方案被传入 MaterialTheme 并反映到各个控件。Text、RadioButton 等组件内部已引用 MaterialTheme 属性，例如：文本颜色默认关联 `colorScheme.primary` 属性，因此它们的外观将会自动变化；我们也可以引用 `MaterialTheme.colorScheme.primary` 等属性实现自定义配置，此处我们将 Icon 着色为 `colorScheme.primary`。

`isSystemInDarkTheme()` 是 Compose 的内置函数，将在系统深色模式开关变化时触发重组，通过该函数即可实现应用深色模式跟随系统配置变更。

### 主题切换
主题在 Material 3 中本质上就是传递不同的配色方案、文本样式等属性给 MaterialTheme，使其内部的组件重新绘制。前文示例中我们只定义了深色与浅色两种配色方案，若要支持更多主题，只需将 `darkMode` 更换为枚举类，并创建对应的配色方案，在 MyTheme 内部根据用户选择的主题枚举切换配色方案即可。

### 主题属性
MaterialTheme 的所有参数如下文代码块所示：

```kotlin
MaterialTheme(
    colorScheme = myColorScheme,
    typography = myTypography,
    shapes = myShapes,
    content = content
)
```

`colorScheme` 即配色方案，用于配置 Material 3 控件的色彩。

- `primary` : 主要颜色，用于基础的文本、按钮等组件。
- `secondary` : 辅色用于界面中不太显眼的组件，例如过滤组件。
- `tertiary` : 第三色用于提供对比鲜明的强调色
- `surface` : Surface 背景颜色。
- `background` : Scaffold 背景颜色。
- `scrim` : Dialog 外侧画面变暗遮罩效果的颜色。
- `error` : 错误提示颜色。



`typography` 是文本样式，可以定义字体、字号、字重等属性。

文本:

val typography = Typography(
    titleMedium = Typography().bodyLarge.copy(
        fontSize = Dimens.Text.Title,
        fontWeight = FontWeight.Bold
    ),
    // 默认文本样式
    bodyLarge = Typography().bodyLarge.copy(
        fontSize = Dimens.Text.Normal,
    )
)


Text(
   text = "you are learning typography",
   style = MaterialTheme.typography.bodyMedium
)

Material 3 中的文本显示类组件默认采用 `MaterialTheme.typography.bodyLarge` 样式。



`shapes` 属性是元素形状，用于定义文本框


```kotlin
val myShapes = Shapes(
    // 影响 TextField、Menu 等组件
    extraSmall = RoundedCornerShape(4.dp),
    // 影响 Chip、Snackbar 等组件
    small = RoundedCornerShape(4.dp),
    // 影响 Card 等组件
    medium = RoundedCornerShape(8.dp),
    // 影响 FAB 等组件
    large = RoundedCornerShape(8.dp),
    // 影响 AlertDialog 等组件
    extraLarge = RoundedCornerShape(8.dp)
)
```

可以改为 RectangleShape 和 CircleShape




按钮等样式

compose没有style系统，我们可以自己将其封装为组件。



## 自定义主题
MaterialTheme 的实现原理是通过 [🧭 CompositionLocal](./01_概述.md#compositionlocal) 向作用域内注入 `colorScheme.primary` 等属性，当主题变量被更新时刷新作用域内的组件树，使得所有组件重组并应用新的颜色、字体样式等。

如果应用程序未使用 Material 3 作为设计风格，或 MaterialTheme 内置属性语义不满足要求，我们也可以通过 CompositionLocal 注入自定义属性，扩展或取代 MaterialTheme。

/* 定义数据类，描述主题属性。 */

`ThemeExtend.kt` :

```kotlin
@Immutable
data class MyTextColors(
    val warning: Color,
    val error: Color
)


// `staticCompositionLocalOf` 不追踪具体组件的读取行为，主题变化时刷新整个组件树，效率更高。
val LocalMyTextColors: ProvidableCompositionLocal<MyTextColors> = staticCompositionLocalOf {
    // 此处提供默认值即可。
    MyTextColors(
        warning = Color.Unspecified,
        error = Color.Unspecified
    )
}
```


`ThemeExtend.kt` :

```kotlin
// 浅色配置
val LightTextColors = MyTextColors(
    warning = Color(0xFFCCCC00),
    error = Color(0xFFFF2F2F)
)

// 深色配置
val DarkTextColors = MyTextColors(
    warning = Color(0xFFEEEE00),
    error = Color(0xFFEF5350)
)
```



`ThemeExtend.kt` :

```kotlin
// 浅色配置
val LightTextColors = MyTextColors(
    warning = Color(0xFFEEEE00),
    error = Color(0xFFEF5350)
)

// 深色配置
val DarkTextColors = MyTextColors(
    warning = Color.Cyan,
    error = Color.Magenta
)


@Composable
fun MyCustomTheme(
    darkTheme: Boolean = isSystemInDarkTheme(),
    content: @Composable () -> Unit
) {
    // 根据传入参数选择对应的主题色实例
    val myTextColors = if (darkTheme) DarkTextColors else LightTextColors

    // 通过 CompositionLocalProvider 向作用域内注入 LocalMyTextColors 变量
    CompositionLocalProvider(LocalMyTextColors provides myTextColors) {
        // 保留 MaterialTheme
        MaterialTheme(
            colorScheme = if (darkTheme) darkColorScheme() else lightColorScheme(),
            content = content
        )
    }
}
```

我们通过 CompositionLocalProvider 向 MyCustomTheme 的作用域内注入 LocalMyTextColors 变量，内部组件可以使用 LocalMyTextColors.current 获取当前值并进行监听。

此处我们保留了 MaterialTheme ，组件即可以使用新增的 MyTextColors 属性，也可以使用 MaterialTheme 属性，如果我们不需要 MaterialTheme，也可以移除MaterialTheme 只调用 content 绘制内部组件。

`TestUICustomTheme.kt` :

```kotlin
Text(text = "警告消息", color = LocalMyTextColors.current.warning)
Text(text = "错误消息", color = LocalMyTextColors.current.error)
```



提供一个单例对象便于访问

`ThemeExtend.kt` :

```kotlin

object MyCustomTheme {

    val textColors: MyTextColors
        @Composable
        get() = LocalMyTextColors.current
}
```


```kotlin
Text(text = "警告消息", color = MyCustomTheme.textColors.warning)
Text(text = "错误消息", color = MyCustomTheme.textColors.error)
```

## 案例一
### 问题描述
Compose 内置的图片数据解码方法 `decodeToImageBitmap()` 返回 ImageBitmap 后，该实例的属性被访问时出现 NPE。

```text
10:56:04.054 5341 5341 E AndroidRuntime: FATAL EXCEPTION: main
                                         Process: net.bi4vmr.study.ui.compose.base, PID: 5341
                                         java.lang.NullPointerException: Attempt to invoke virtual method 'int android.graphics.Bitmap.getWidth()' on a null object reference
                                             at androidx.compose.ui.graphics.AndroidImageBitmap.getWidth(AndroidImageBitmap.android.kt:68)
                                             at androidx.compose.ui.graphics.painter.BitmapPainterKt.BitmapPainter-QZhYCtY$default(BitmapPainter.kt:49)
                                             at androidx.compose.foundation.ImageKt.Image-5h-nEew(Image.kt:158)
                                             at net.bi4vmr.study.base.ComposableSingletons$TestUIBaseKt.lambda__363668594$lambda$0(TestUIBase.kt:35)
```

### 问题分析
`decodeToImageBitmap()` 方法不会检查输入数组的内容是否为空，当数组内容为空时，ImageBitmap也能正常被返回，但此时其中的 Bitmap 为空值，一旦宽度、高度等接口被调用，就会出现 NPE 。

```kotlin
// 测试图像数据（内容为空的字节数组，模拟数据损坏的情况。）
val iconBytes: ByteArray = byteArrayOf()

// 错误示范：直接使用 `decodeToImageBitmap()` 方法解码。
// val icon = iconBytes.decodeToImageBitmap()

```

### 解决方案


// 正确示范：使用 `BitmapFactory.decodeByteArray()` 方法解码，并处理解码失败时的空值。
val icon: ImageBitmap =
    BitmapFactory.decodeByteArray(iconBytes, 0, iconBytes.size)?.asImageBitmap()
        ?: ImageBitmap.imageResource(R.drawable.ic_funny_256)
Image(
    icon,
    contentDescription = null,
    modifier = Modifier.padding(innerPadding)
)



fun ByteArray?.decodeToImageBitmapSafe(context: Context, @DrawableRes default: Int): ImageBitmap {
    val defImg = ImageBitmap.imageResource(context.resources, default)
    // 快速路径：对输入无效的情况直接返回默认值
    if (this == null) return defImg
    if (this.isEmpty()) return defImg

    return BitmapFactory.decodeByteArray(this, 0, this.size)?.asImageBitmap()
        ?: defImg
}


fun ByteArray?.decodeToImageBitmapSafe(): ImageBitmap? {
    // 快速路径：对输入无效的情况直接返回空值
    if (this == null) return null
    if (this.isEmpty()) return null

    return BitmapFactory.decodeByteArray(this, 0, this.size)?.asImageBitmap()
}
