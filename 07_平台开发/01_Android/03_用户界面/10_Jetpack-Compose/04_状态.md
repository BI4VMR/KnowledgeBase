# 简介
应用的“状态”是指可以随时间变化的任何值。这是一个非常宽泛的定义，从 Room 数据库到类的变量，全部涵盖在内。

注意：优秀实践是为所有可组合函数提供默认的 Modifier，从而提高可重用性。它应作为第一个可选参数显示在参数列表中，位于所有必需参数之后。

# 基本应用
在前文示例中，我们习惯通过 `var count: Int by remember { mutableIntStateOf(0) }` 语句定义 Compose 状态以驱动界面更新，本节内容将讨论状态定义语句中各个部分的作用。

🔴 示例一：缺少 `mutableStateOf()` 的状态变量。

在本示例中，我们声明状态变量但不使用 `mutableStateOf()` 方法，并观察运行时的行为。

`TestUIBase.kt` :

```kotlin
@Composable
fun Counter() {
    // 声明状态变量，但不使用 `mutableStateOf()` 方法。
    var count: Int = remember { 0 }

    Column {
        Text("当前数值：[$count]")
        Row {
            Button(onClick = { count++ }) {
                Text("数值增加")
            }
            Button(onClick = { count-- }) {
                Text("数值减少")
            }
        }
    }
}
```

此时运行示例程序，并点击界面上的按钮，我们发现文本框中显示的 `count` 数值并未发生变化，始终为 `0` 。

Compose 仅能观察 `MutableState<T>` 类型变量的变化， `remember { 0 }` 语句创建了 Int 类型的普通变量，其数值变化无法被 Compose 观察，因此文本框内容未正常更新。由此可知， `mutableStateOf()` 部分是必不可少的。

除了前文示例中所使用的 `mutableIntStateOf()` 方法，我们还可以按需选用以下方法创建 `MutableState<T>` 变量：

- `mutableLongStateOf(<初始值>)` : Long 类型的状态容器。
- `mutableFloatStateOf(<初始值>)` : Float 类型的状态容器。
- `mutableDoubleStateOf(<初始值>)` : Double 类型的状态容器。
- `mutableStateOf(<初始值>)` : 任意类型的状态容器。

🟠 示例二：缺少 `remember()` 的状态变量。

在本示例中，我们声明状态变量但不使用 `remember()` 方法，并观察运行时的行为。

`TestUIBase.kt` :

```kotlin
@Composable
fun Counter2() {
    // 声明状态变量，但不使用 `remember()` 方法。
    var count: Int by mutableIntStateOf(0)

    Column {
        Text("当前数值：[$count]")
        Row {
            Button(onClick = { count++ }) {
                Text("数值增加")
            }
            Button(onClick = { count-- }) {
                Text("数值减少")
            }
        }
    }
}
```

此时运行示例程序，并点击界面上的按钮，我们发现文本框中显示的 `count` 数值并未发生变化，始终为 `0` 。

当我们按下任意按钮修改状态变量 `count` 中的数值时， Compose 感知到变化并重组 Counter2 控件， `var count: Int by mutableIntStateOf(0)` 语句将被重新执行， `count` 变量重新初始化且内容为 `0` ，因此文本框显示的数值也为 `0` 。

由此可知， `remember()` 部分是必不可少的，它的作用是在组件重组期间记住状态变量中的内容。

🟡 示例三：缺少 `by` 的状态变量。

在本示例中，我们声明状态变量但不使用 `by` 关键字，并观察运行时的行为。

`TestUIBase.kt` :

```kotlin
@Composable
fun Counter3() {
    // 声明状态变量，但不使用属性委托。
    val count: MutableState<Int> = remember { mutableIntStateOf(0) }

    Column {
        Text("当前数值：[${count.value}]")
        Row {
            Button(onClick = { count.value++ }) {
                Text("数值增加")
            }
            Button(onClick = { count.value-- }) {
                Text("数值减少")
            }
        }
    }
}
```

此时运行示例程序，并点击界面上的按钮，我们发现文本框中显示的 `count` 数值能够同步变化。

`by` 关键字能够将 `count` 属性的读写动作委托给 `androidx.compose.runtime.getValue()` 和 `androidx.compose.runtime.setValue()` 方法，该部分是可选的。未添加关键字时 `count` 变量类型为 `MutableState<Int>` ，我们需要通过 `count.value` 读写状态容器的内容；添加关键字后， `count` 变量为 Int 类型，读写 `count` 变量等同于读写 `MutableState<Int>` 容器的内容，后者相比前者更为简洁。

当我们使用 `remember {}` 包裹状态变量后，组件每次被重组时状态变量都不会改变。有时我们希望在特定条件下重置状态变量，可以通过 `remember(key) {}` 系列方法实现，一旦参数 `key` 的值发生变化，其中的状态变量就会被重置为初始值。

🟢 示例四：重置状态。

在本示例中，我们为状态变量添加重置条件。

`TestUIBase.kt` :

```kotlin
@Composable
fun UserInfo() {
    // 用户 ID
    var id: Int by remember { mutableIntStateOf(1) }

    // 用户名称
    var name: String by remember(id) { mutableStateOf("") }

    Column {
        Text("用户名称")
        TextField(
            value = name,
            onValueChange = { name = it }
        )
        Spacer(Modifier.height(16.dp))
        Button(onClick = { id++ }) {
            Text("切换用户")
        }
    }
}
```

在上述代码中，我们将用户 ID 作为用户名称的重置条件，一旦“切换用户”按钮被点击， ID 数值发生变化，状态变量 `name` 就会重新执行 `mutableStateOf("")` 语句初始化，丢弃旧的状态。

除了具有单个 `key` 参数的 `remember()` 方法之外， Compose 还提供了具有多个 `key` 参数的方法，任意 `key` 发生变化都会触发状态变量重置，我们可以根据实际需要选用。


# 状态保持
`remember()` 能在控件被重组时记住状态变量，但在屏幕旋转等会使整个 Activity 销毁并重新创建的场景中，状态变量仍然会被重置。

🔵 示例五：比较 `remember()` 和 `rememberSaveable()` 的行为。

在本示例中，我们声明两个状态变量，并观察运行时的行为。

`TestUIStateSave.kt` :

```kotlin
@Composable
fun Counter() {
    var count: Int by remember { mutableIntStateOf(0) }

    Column {
        Text("当前数值：[$count]")
        Row {
            Button(onClick = { count++ }) {
                Text("数值增加")
            }
            Button(onClick = { count-- }) {
                Text("数值减少")
            }
        }
    }
}

@Composable
fun Counter2() {
    var count: Int by rememberSaveable { mutableIntStateOf(0) }

    // 与 `Counter` 控件一致，显示当前数值并通过按钮改变数值，此处省略具体实现。
}
```

此时运行示例程序，并点击界面上的按钮，然后旋转屏幕使界面重建。我们发现 Counter 组件的数值被重置为 `0` ，而 Counter2 组件的数值仍能保持屏幕旋转之前的状态。

`remember()` 通常用于记录临时性的状态，整个界面重组时允许被重置。例如：动画播放进度、等。
`rememberSaveable()` 用于记录整个界面重建也需要保持的状态，，如用户输入、选项卡选中状态等，

除了通过 `rememberSaveable()` 保存界面状态，我们还可以在ViewModel中使用可观察变量表示状态，并在Compose组件中使用。


🟣 示例六：将 Kotlin Flow 作为 Compose 状态。

在本示例中，我们将 Kotlin Flow 作为 Compose 状态。

`TestUIStateSave.kt` :

```kotlin
@Composable
fun Counter3() {
    // 在界面 `onStart()` 时监听数据，在界面 `onStop()` 时取消监听数据。
    val count: Int by viewModel.count.collectAsStateWithLifecycle()

    Column {
        Text("当前数值：[$count]")
        Row {
            Button(onClick = { viewModel.add() }) {
                Text("数值增加")
            }
            Button(onClick = { viewModel.reduce() }) {
                Text("数值减少")
            }
        }
    }
}
```

## 副作用
非ui状态的操作

网页/API 数据请求

弹出一个 Toast 或 Snackbar

注册一个传感器/广播监听器

跳转页面或修改全局变量

重组不可预期，如果直接将此类操作写在compsoe方法内，将会频繁刷新，文本框输入文本，输入一个字刷新一次。


副作用：每当key改变时执行回调，可以执行协程

LaunchedEffect(key) {
    ...
}

key可以有多个，任意key变化都会触发，可以实现级联更新。

组件初始化时必然会执行一次

如果希望组件初始化时运行一次，不需要跟随状态变化，key可以传入Unit。



副作用：每当key改变时执行onDispose回调进行清理，再执行onDispose之前的语句，此处不能执行协程

DisposableEffect(key) {
    ...

    onDispose {
        // 清理操作
    }
}

组件初始化时必然会执行一次onDispose前的语句。
