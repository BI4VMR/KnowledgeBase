# 返回值

如果 `main()` 方法正常运行完毕，JVM将会向系统发送进程状态码"0"；如果其在运行过程中发生错误，导致进程异常终止，JVM将会向系统发送进程状态码"1"。

Linux系统中的环境变量 `$?` 即代表前一个任务的返回值，我们在Shell中运行以上代码，并查看返回值：

```text
# 编译并运行示例程序
[root@Fedora ~]$ java FirstDemo.java
Hello World!

# 读取上一个进程的状态码
[root@Fedora ~]$ echo "$?"
0
```

除了正常顺序运行的逻辑外，我们还可以根据需要，在代码中的任意位置调用 `System.exit(int code)` 方法终止主进程，并配置自定义的状态码"code"。

部分命令在windows不正常，linux或mac正常

windows 启动进程时会自动为命令前后加上双引号，如果原始命令也包含双引号，就会出现歧义，例如：

adb shell touch "/sdcard/test file.txt"

表示在android设备上执行  touch "/sdcard/test file.txt" ，为确保带有空格的文件名正确识别，此处我们添加了双引号

当我们用java执行时

ProcessBuilder("adb", "shell", "touch \"/sdcard/test file.txt\"")

在类 unix平台，参数将直接传递给子进程，上述命令消解java转义符号后为 adb shell touch "/sdcard/test file.txt" ，与预期一致，所以不会出错。

在windows上，java进程为 touch "/sdcard/test file.txt" 添加双引号并传给子进程，子进程看到的是 "touch "/sdcard/test file.txt""

此时按照双引号分段规则进行解析，参数列表为：

touch /sdcard/test
file.txt
<空字符串>

所以会导致执行失败。


需要在windows远程执行unix shell命令时，最好用单引号

ProcessBuilder("adb", "-s", "172.16.7.1", "shell", "touch \'/sdcard/test file.txt\'")

windows 不会处理单引号，因此没问题。

如果远程命令需要使用双引号+变量取值，建议将文本写入目标设备的临时文件作为脚本执行，不要直接在命令行中操作


转义与引号

命令行中的转义是给shell看的，例如

cat "test file.txt"

这里我们为了确保带有空格的文件名能够正确传递，所以需要加上引号。shell将命令与参数传递给子进程时会去除引号与转义，子进程收到的参数列表为 cat test file.txt ，不包括引号。

当我们使用process时，需要将命令与参数拆分为数组，并确保其中没有转义符号与引号。
